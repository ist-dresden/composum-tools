text search patterns...

  • all terms are combined with AND, '+' starts a new AND group which is combined with OR
  • if the first term starts with a '/' it's used as search path, otherwise '/content' is used
  • the path can be prepended by the [primary:type] of the searched resources
  • each term can be prepended by a [property/path]; '-' negates a term (NOT)
  • each term can contain or start/end with '*' wildcards
  • a quoted text term can contain spaces, e.g. "this phrase is searched"
  • if a '=' operator is prepended the property must be equal instead of 'like' or 'contains()'

placehoders

  • \${path} - represents the current path of the browser
  • \${1}, \${2}, \${3} - 1..3 optional arguments filled with the values of the automatically shown argument input fields

text search examples...

  • [cq:PageContent]/content/my/site *likepattern*
  • /content/my/site -[jcr:title]*likepattern*
  • /content/my/site [jcr:title]="property value" +"alternative like pattern"
XPATH search examples...
  • /conf//en[jcr:mixinTypes='mix:language']
